# Вся халява — личные подписки

Бот @vsyaHalyava_bot читает новые сообщения существующей общей группы и
рассылает копии пользователям, которые сами выбрали соответствующие категории.
Общий поток и действующий сканер не изменяются. Сервис также запускает перенесённый Twitch/Telegram/VK-сканер: локальный
компьютер после переключения не нужен.

## Пользователь

- `/start` или `/menu`: пять переключателей — BetBoom, Upgrader, Caser,
  Magic Drop, Жабка. Изначально ничего не включено.
- «Включить всё»: все пять категорий.
- `/stop` или «Отключить всё»: удалить выбор и отменить ожидающие доставки.
- Бот не может первым начать личный диалог. Пользователь сначала нажимает Start.
- Приходят только новые сообщения после включения категории, без старого архива.

## Источник и защита от лишней рассылки

Бот должен быть администратором исходной группы с минимальными правами,
чтобы получать обычные сообщения. Проверяется идентификатор группы,
идентификатор отправителя сканера и формат заголовка сообщения. Обычная
переписка участников не рассылается. Категория определяется по оформленному
сканером заголовку и ссылкам до блока «Оригинал», чтобы чужая реклама в цитате
не добавила неправильную категорию.

## Хранение и доставка

SQLite хранит рабочие данные сканера и предпочтения, обработанные сообщения,
позицию чтения и очередь бота.
Одинаковая публикация обрабатывается один раз; исправление уже разосланного
поста не создаёт новую рассылку. Новый пост с тем же колесом может пройти:
30-минутный КД BetBoom и правила остальных категорий остаются в сканере.
При блокировке бота пользователем рассылка ему выключается. Ограничения 429
и временные сетевые ошибки повторяются с задержкой. Удалённые/недоступные
исходные сообщения помечаются как недоставленные. При неопределённом сетевом
сбое после принятия копии Telegram возможна повторная доставка: Bot API не
предоставляет ключ идемпотентности для copyMessage.

## Запуск

Python 3.11+, `pip install -r requirements.txt`, `python bot.py`.
Настройки передаются переменными окружения, см. `.env.example`.
Токены, Telegram-сессии и базы в репозиторий не помещать.
Одновременно запускается только один экземпляр бота.

## Render Free

Бесплатный Web Service, Python, build: `pip install -r requirements.txt`,
start: `python web.py`, health endpoint: `/healthz`.
События приходят через Telegram webhook `/telegram` с секретным заголовком.
Обе рабочие базы SQLite сохраняются зашифрованными снимками в таблицу
Supabase PostgreSQL через пулер подключений. Ключ Fernet и строка подключения
хранятся в окружении Render. Тексты обычных участников не сохраняются.

Обязательные переменные: BOT_TOKEN, SOURCE_CHAT_ID, SCANNER_SENDER_IDS,
WEBHOOK_SECRET, DATABASE_URL, STATE_ENCRYPTION_KEY. Сохраняйте ключ
шифрования: без него восстановить настройки невозможно. Не запускайте два
экземпляра.

GitHub Actions делает запрос к `/healthz` каждые 10 минут; адрес берётся из
repository variable `RENDER_URL`. Расписание GitHub может задерживаться,
а при 60 днях без активности публичного репозитория отключается.
Free Render ограничивает число бесплатных часов на workspace.
Это уменьшает вероятность сна, но не гарантирует бесперебойные 24/7.
Если сервис уснул, Telegram webhook разбудит его; возможна задержка старта.
При аварии после отправки, но до сохранения снимка, возможен дубль. Ответы
на команды не ждут завершения фонового сохранения; временная ошибка БД
повторяется, а `/healthz` показывает проблему до восстановления снимка.

## Проверка

`python -m unittest discover -v`

Проверки не публикуют сообщений в живой группе и не отправляют рассылку
реальным людям. Проверяются фильтрация источника, выбор категорий, остановка,
сохранение настроек, очередь, повторы и обработка ошибок API.

## Облачный сканер

ENABLE_SCANNER=1 включает scanner_cloud.py в том же процессе.
Настройки: TWITCH_TOKEN, TG_API_ID, TG_API_HASH, TG_FORWARD_GROUP,
TG_STRING_SESSION, VK_TOKEN; SCANNER_DATA_DIR=/tmp/halyava.
Сессия Telegram хранится только в секретных переменных Render.
Зашифрованный снимок сканера содержит каналы, промокоды и историю КД;
он восстанавливается при старте и обновляется каждые 30 секунд.
В аварийной остановке последние 30 секунд изменений могут не сохраниться.
Старый локальный сканер нельзя запускать параллельно с облачным.
Проверка /scanner-status требует секретный заголовок webhook.
Free и внешний keep-warm не дают SLA: возможны паузы, особенно потеря
сообщений Twitch во время сна/перезапуска; история IRC не восстанавливается.

## Ограничения Twitch

Один аккаунт может одновременно состоять не более чем в 100 обычных чатах.
Сервис держит один IRC WebSocket и считает только подтверждённые JOIN.
Сначала выбираются каналы в эфире; свободные места занимают офлайн-каналы.
Выбор пересчитывается примерно каждые 5–7 минут с учётом времени JOIN.
Если эфиров больше 100, они тоже ротируются. Неподключённые в данный момент
чаты не читаются, история Twitch не восстанавливается. Недоступные каналы и
бан аккаунта отмечаются отдельно в scanner-status. Это не полный
одновременный охват всей базы из 273 каналов.


## Управление источниками

ADMIN_IDS — разрешённые ID владельцев через запятую; по умолчанию доступ закрыт.
В личке /admin показывает команды /status, /channels, /jobs, /addtg,
/addtwitch, /deltg, /deltwitch. Проверяется ID отправителя и личного чата.
Telegram принимает публичный username и подписывает аккаунт сканера.
Удаление выключает сканирование, но не отписывает аккаунт Telegram.
Изменения Twitch применяются при очередной ротации, обычно до 7 минут.
Административные операции сохраняются в admin_jobs; повтор одной команды
с тем же message_id не создаёт новую задачу. Успешный результат выдаётся после
сохранения снимка сканера в Supabase; временные ошибки повторяются в фоне.
